# Factory Contract

The Factory is the central orchestrator of the FEY Protocol, responsible for token deployment, system configuration, and fee management.

**Contract Address**: `0x8EEF0dC80ADf57908bB1be0236c2a72a7e379C2d`

## Overview

The Factory contract serves as the entry point for token deployments and the control center for protocol-wide settings. It coordinates with all other system components to create a seamless deployment and fee distribution experience.

### Key Responsibilities

- **Token Deployment**: Creates new FEY-compatible tokens with 100B supply
- **Pool Initialization**: Sets up Uniswap V4 pools with hooks and configuration
- **System Configuration**: Manages enabled modules (hooks, lockers, extensions, MEV)
- **Fee Routing**: Routes WETH and FEY fees to appropriate destinations
- **Access Control**: Owner/admin/bootstrap role management

## Core Functions

### Token Deployment

#### deployToken

```solidity
function deployToken(DeploymentConfig memory deploymentConfig)
    public payable nonReentrant
    returns (address tokenAddress)
```

The main function for creating new tokens with full liquidity pool setup. Requires comprehensive configuration and can include ETH for extensions.

**Parameters:**
- `deploymentConfig`: Complete deployment configuration including:
  - `tokenConfig`: Token metadata, admin, salt, and chain ID
  - `poolConfig`: Pool hook, paired token, tick configuration
  - `lockerConfig`: LP positions, reward distribution
  - `mevModuleConfig`: MEV protection module
  - `extensionConfigs[]`: Array of extension configurations

**Returns:**
- `tokenAddress`: Address of the newly created token

**Process:**
1. Validates deployment is allowed (not deprecated, or using bootstrap)
2. Creates token via `FeyDeployer.deployToken()` with 100B supply
3. Initializes pool through hook contract
4. Sets up liquidity positions via locker
5. Executes extensions (dev buys, etc.) with provided ETH
6. Enables MEV protection
7. Stores deployment info for tracking
8. Emits `TokenCreated` event

**Value:**
- Must send ETH equal to sum of all `extensionConfigs[].msgValue`
- If no extensions, send 0 ETH

#### deployTokenZeroSupply

```solidity
function deployTokenZeroSupply(TokenConfig memory tokenConfig)
    public nonReentrant
    returns (address tokenAddress)
```

Creates a token with zero supply (no initial liquidity pool). Useful for tokens that will be deployed on other chains first, or for custom liquidity setup.

**Parameters:**
- `tokenConfig`: Basic token configuration (name, symbol, metadata, admin, salt, chain ID)

**Returns:**
- `tokenAddress`: Address of the newly created token

**Differences from deployToken:**
- No pool initialization
- No liquidity positions
- No extensions
- No MEV module
- Token starts with 0 supply
- Can be used for cross-chain deployments where liquidity is added later

### Fee Management

```solidity
function claimWethFees() external nonReentrant
function claimBaseTokenFees() external nonReentrant
```

Public functions for routing accumulated fees to their destinations.

**claimWethFees:**
- Transfers all WETH balance to `teamFeeRecipient`
- Used for manual buyback process
- Can be called by anyone

**claimBaseTokenFees:**
- Routes FEY fees to `feeLocker` (if set) or `teamFeeRecipient`
- Automatic storage for staker distribution
- Can be called by anyone

### System Configuration

#### Module Management

```solidity
function setHook(address hook, bool enabled) external onlyOwnerAdminOrBootstrap
function setLocker(address locker, address hook, bool enabled) external onlyOwnerAdminOrBootstrap
function setExtension(address extension, bool enabled) external onlyOwnerAdminOrBootstrap
function setMevModule(address mevModule, bool enabled) external onlyOwnerAdminOrBootstrap
function setAdmin(address admin, bool enabled) external onlyOwnerAdminOrBootstrap
```

Administrative functions for configuring protocol modules.

**Access Control:**
- `onlyOwnerAdminOrBootstrap`: Owner, admin, or bootstrap can call
- Bootstrap permissions can be released permanently
- Some settings can be frozen permanently

**Module Enablement:**
- Hooks: Enable/disable pool hooks for deployments
- Lockers: Enable locker/hook combinations
- Extensions: Add/remove approved extensions
- MEV Modules: Enable/disable MEV protection modules
- Admins: Grant/revoke admin privileges

#### Core Configuration

```solidity
function setBaseToken(address baseToken_) external onlyOwnerAdminOrBootstrap
function setBootstrap(address bootstrap_) external onlyOwnerAdminOrBootstrap
function setDeprecated(bool deprecated_) external onlyOwnerAdminOrBootstrap
function setTeamFeeRecipient(address teamFeeRecipient_) external onlyOwner
function setFeeLocker(address feeLocker_) external onlyOwner
function setHookBaseToken(address hook) external onlyOwnerAdminOrBootstrap
```

**Critical Settings:**
- `setBaseToken`: Sets the FEY base token (bootstrap only initially)
- `setBootstrap`: Sets bootstrap address (can be released)
- `setDeprecated`: Pauses new deployments (owner/admin)
- `setTeamFeeRecipient`: Sets fee recipient (owner only, can be frozen)
- `setFeeLocker`: Sets fee locker for stakers (owner only, can be frozen)
- `setHookBaseToken`: Configures hook's base token reference

#### Freeze Functions

```solidity
function freezeTeamFeeRecipient() external onlyOwner
function freezeFeeLocker() external onlyOwner
```

Permanently locks critical addresses. Once frozen, these addresses cannot be changed, providing security guarantees for users.

## Access Control

### Role Hierarchy

**Owner** (Highest privileges)
- Set all system parameters
- Freeze critical settings
- Manage admin roles

**Admin**
- Configure modules and extensions
- Manage non-critical settings
- Trigger fee claims

**Bootstrap**
- Special role for initial setup
- Can be permanently released
- Required for initial base token setting

### Security Features

```solidity
function freezeTeamFeeRecipient() external onlyOwner
function freezeFeeLocker() external onlyOwner
```

Permanent freeze mechanisms for critical addresses:
- Once frozen, addresses cannot be changed
- Provides security guarantees for users
- Irreversible protection against malicious changes

## Events

### Token Creation

```solidity
event TokenCreated(
    address indexed msgSender,        // Address that called deployToken
    address indexed tokenAddress,      // Newly created token address
    address indexed tokenAdmin,        // Token admin address
    string tokenImage,                // Token image URL
    string tokenName,                 // Token name
    string tokenSymbol,               // Token symbol
    string tokenMetadata,              // Token metadata URL
    string tokenContext,               // Additional context string
    int24 startingTick,                // Starting price tick
    address poolHook,                  // Pool hook address
    PoolId poolId,                    // Uniswap V4 pool ID (bytes32)
    address pairedToken,               // Paired token (FEY)
    address locker,                    // LP locker address
    address mevModule,                 // MEV module address
    uint256 extensionsSupply,          // Total supply allocated to extensions
    address[] extensions               // Array of extension addresses used
);
```

**Event Details:**
- Emitted on successful token deployment via `deployToken()`
- Contains complete deployment information
- Use `tokenAddress` to track new tokens
- `extensionsSupply` shows total tokens sent to extensions
- `extensions[]` lists all extension contracts that received tokens

**Parsing with SDK:**
```typescript
import { parseTokenCreatedEvent } from '@dutchiono/fey-sdk';

const receipt = await provider.getTransactionReceipt(txHash);
const event = parseTokenCreatedEvent(receipt);

if (event) {
  console.log('Token:', event.tokenAddress);
  console.log('Admin:', event.tokenAdmin);
  console.log('Name:', event.tokenName);
  console.log('Symbol:', event.tokenSymbol);
  console.log('Hook:', event.poolHook);
  console.log('Locker:', event.locker);
  console.log('Extensions:', event.extensions);
}
```

## Usage Examples

### Using the Official SDK

The recommended way to interact with the Factory contract is through the official SDK:

```typescript
import {
  buildSimpleDeployTokenTx,
  parseTokenCreatedEvent,
  getTokenDeploymentInfo,
  getFeyFactoryContract,
  FEY_FACTORY_ADDRESS,
} from '@dutchiono/fey-sdk';
import { ethers } from 'ethers';

const provider = new ethers.JsonRpcProvider('https://mainnet.base.org');
const signer = new ethers.Wallet(PRIVATE_KEY, provider);

// Deploy a token
const tx = buildSimpleDeployTokenTx({
  tokenAdmin: await signer.getAddress(),
  name: 'My Token',
  symbol: 'TKN',
  image: 'ipfs://Qm...',
  metadata: 'ipfs://Qm...',
  context: '',
  originatingChainId: 8453n,
});

const txResponse = await signer.sendTransaction(tx);
const receipt = await txResponse.wait();

// Parse the TokenCreated event
const event = parseTokenCreatedEvent(receipt);
if (event) {
  console.log('Token deployed at:', event.tokenAddress);
  console.log('Token admin:', event.tokenAdmin);
  console.log('Pool hook:', event.poolHook);
  console.log('Locker:', event.locker);
}

// Query deployment info
const info = await getTokenDeploymentInfo(provider, event.tokenAddress);
console.log('Complete deployment info:', info);
```

### Manual Contract Interaction

```javascript
// Get complete deployment details for a token
const deploymentInfo = await factory.tokenDeploymentInfo(

console.log("Locker:", deploymentInfo.locker);

console.log("Token:", basicInfo.token);

console.log("Locker:", basicInfo.locker);
```

### Check Module Status

```javascript
// Check if a hook is enabled
const hookEnabled = await factory.enabledHooks(hookAddress);

// Check if a locker/hook combination is enabled
const lockerEnabled = await factory.enabledLockers(lockerAddress, hookAddress);

// Check if an extension is enabled

// Check if an MEV module is enabled

```

### Check System Status

```javascript
// Verify factory configuration
const isDeprecated = await factory.deprecated();
const baseToken = await factory.baseToken();

// Get constants

const maxExtensionBps = await factory.MAX_EXTENSION_BPS();
const tokenSupply = await factory.TOKEN_SUPPLY();

```

## Integration Notes

### Using the Official SDK

The recommended approach is to use the official Fey SDK:

```typescript
import {
  buildSimpleDeployTokenTx,
  parseTokenCreatedEvent,
  getTokenDeploymentInfo,
  validateDeployPayload,
} from '@dutchiono/fey-sdk';

// Validate payload before deployment
const validation = validateDeployPayload(payload);
if (!validation.valid) {
  throw new Error(validation.errors.join(', '));
}

// Build and send transaction
const tx = buildSimpleDeployTokenTx(payload);
const receipt = await signer.sendTransaction(tx).then(tx => tx.wait());

// Parse event to get token address
const event = parseTokenCreatedEvent(receipt);
```

See the [SDK Guide →](/guides/sdk) for complete documentation.

### For Frontend Developers

**Token Deployment Interface:**
1. Use `buildSimpleDeployTokenTx()` from the SDK
2. Collect deployment configuration from user
3. Validate with `validateDeployPayload()`
4. Send transaction with appropriate ETH value
5. Parse `TokenCreated` event for deployment confirmation

**Fee Monitoring:**
1. Track fee accumulation in factory
2. Provide UI for triggering fee claims
3. Show real-time protocol revenue

### For Protocol Integrators

**Module Integration:**
1. Implement required interfaces (IFeyExtension, IFeyLpLocker, etc.)
2. Get module approved via admin functions
3. Test integration with deployment flow

**State Monitoring:**
1. Monitor deployment events for new tokens using `parseTokenCreatedEvent()`
2. Track fee flows and distributions
3. Query deployment info using `getTokenDeploymentInfo()`
